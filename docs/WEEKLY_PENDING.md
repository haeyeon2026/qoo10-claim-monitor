# 위클리 변경 요구사항 — 아직 구현하지 않음

사용자 지시(2026-09-29): 데일리와 위클리는 서로 다른 시점의 상태 집계다. 먼저 실행 방안을 설명하고 코드는 변경하지 않는다.

## 합의한 의미

- 데일리: 매일 수집 당시의 상태를 보관한다. 현재 운영은 평일 오전 9시이며 월요일에 금·토·일 발송 건을 처리한다.
- 위클리: 매주 금요일, 전주 금요일부터 이번 주 목요일까지 발송된 메일을 대상으로 상태를 다시 조회해 그 시점의 주간 수치를 저장한다.
- 제시한 실행 시간은 금요일 오전 9시(한국·일본 UTC+9)다.
- 예: 2026-10-02에 2026-09-25~2026-10-01 발송 건을 조회한다.
- 데일리의 요청 대기가 금요일에 고객 승인으로 바뀌면 위클리에는 고객 승인으로 집계한다.
- 일별 기준값은 덮어쓰지 않고, 주간 재조회 결과와 실행 시각을 별도 보관한다.
- 주간용 조회 실패는 과거 상태를 현재 상태처럼 대신 쓰지 않고 미확인으로 표시한다.
- 금요일 외에는 별도 주간 재조회를 하지 않는다.
- 성공 건 자동 재수집 금지 규칙의 예외는 이 주간 상태 조회 범위로만 한정한다. 대화·모니터링 전체 재수집으로 확대하지 않는다.

## 현재 구현과 차이

현재 코드는 저장된 일별 자료를 금~목으로 합산한다. 위의 금요일 재조회는 아직 구현하지 않았다.
구현 전 중복 실행 방지, 주간별 저장 구조, 데일리와 동시 실행 조정, 사전 보고 및 완료 알림을 설계·검증해야 한다.
