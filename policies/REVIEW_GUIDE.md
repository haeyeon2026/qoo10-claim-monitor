- 처방전 제출 안내와 그 이후 미제출 취소 명시를 함께 확인하며, 고객의 회신이 있으면 자동 확정하지 않습니다. 실제 의료적 적합성을 판정하는 기능이 아닙니다.
- 주소 오류 설명과 실제 취소 안내가 같은 메시지의 서로 다른 문장이어도 연결합니다. 과거 주문만의 문제, 질문/가정, 셀러의 주소 입력 실수는 고객 귀책으로 확대하지 않습니다.
- 고객이 이후 `そのまま購入希望`처럼 구매 유지 의사를 밝히면 앞선 취소 요청만으로 정상 처리라고 확정하지 않습니다.


## 사용

기존 http://127.0.0.1:53169/#monitoring 에서 새로고침합니다. Daily·Weekly와 모니터링 모두 1011 확인 요청 메일을 대상으로 합니다.

- 기본 목록은 미확정 악용 의심·검토 필요·판단 불가 주문입니다. 고객 사정 근거가 확인된 주문과 확정한 결과는 `전체 주문`에서 볼 수 있습니다.
- 동일 발송일의 같은 주문·카트를 한 줄로 묶고 10주문씩 표시합니다. 메일 건수는 각각 유지합니다.
- `근거` → 원문·작성자·채널·시각 확인 → `악용 맞음 / 악용 아님 / 판단 보류` → 선택 사유 입력 → `판단 저장` 순서입니다.
- 저장한 판단은 재시작해도 유지되며 같은 화면에서 정정할 수 있습니다. 이전 기록도 삭제하지 않습니다.
- 주문의 자동 분류와 내 판단은 별도로 표시합니다. 재조회로 판단 근거가 달라지면 이전 판단에 재확인 표시를 붙입니다.

## 화면 사용

- 발송일을 고른 뒤 `검토할 주문 / 악용 의심 / 검토·확인 필요 / 고객 사정 / 전체`로 목록을 좁힐 수 있습니다. 필터 숫자는 선택한 날짜의 주문 묶음 수입니다.
- `주문 찾기`에서 주문번호, 카트번호, Buyer 또는 Seller ID로 검색합니다.
- 왼쪽 목록에서 주문을 선택하면 오른쪽에 자동 판단·신뢰도, 취소로 이어진 순서, 핵심 근거를 표시합니다. 긴 원문은 `대화 · 발송 흐름 전체 보기`를 펼쳐 확인합니다.
- `내 판단`을 선택하고 필요하면 `판단 사유 남기기`를 펼친 뒤 저장합니다. 입력 중 새로고침은 메모를 보존하며, 다른 주문이나 날짜로 이동할 때는 미저장 내용을 확인합니다.
- 수집 기간·자동 집계·진행 기록은 상단 `수집 설정 · 기록`에 있습니다.

## 근거 수집

1. 저장된 1011의 모든 주문을 조회해 Buyer ID, Seller ID, 양측 회원번호를 확인합니다.
2. Message/Memo의 Buyer ID 검색 결과에서 Qpost와 出品者掲示板만 확인합니다. Seller ID가 다른 이력은 제외합니다.
3. Inquiry 상세의 구매자가 주문의 Buyer ID 또는 확인된 숫자 회원번호와 일치해야 합니다. 목록의 작성자가 셀러인 발신 메시지도 포함합니다.
4. 주문번호가 직접 연결된 대화는 해당 주문만 사용합니다. 다른 주문에 연결된 대화는 원칙적으로 사용하지 않습니다. 아래 v8·v11의 같은 카트 주소 안내는 원문 출처를 유지해 예외 적용합니다.
5. 주문번호가 없는 대화는 동일 Buyer·Seller이며 각 메일 발송 전 72시간에 작성된 문의·답변만 후보 근거로 사용합니다. 같은 기간에 여러 대상 주문이 겹치면 확정 연결하지 않습니다.
6. 직접 연결된 발송 후 대화는 전체 흐름에 표시하되 그보다 앞선 요청의 정당화 근거로 사용하지 않습니다.
7. 주문의 Claim History → Buyer-Fault Claim 전체 행에서 Status, changed by dt, changed by id, seller_msg, buyer_msg를 함께 수집합니다. 화면에 잘린 문장이 아닌 전체 값을 저장합니다. 정상 인증된 관리자 페이지에서 팝업과 동일한 읽기 요청·표 형식 설정을 사용하며, 반환된 주문번호·열 수·날짜 형식을 검증합니다.
8. Claim History는 변경 이력의 스냅샷이므로 같은 메시지가 여러 행에 남아 있으면 최초 확인 행에 한 번만 표시합니다. 메시지 열과 변경자 ID가 해당 주문의 Seller/Buyer ID 또는 회원번호와 일치할 때만 작성자를 확인한 시간 근거로 사용합니다. 불일치하면 작성자 확인이 필요한 자료로 남깁니다.

주문 미연결 문의에서 단순히 고객 요청을 찾지 못했다고 악용으로 확정하지 않습니다. 조회 실패는 판단 불가이며, 500행 조회 상한에 도달하면 완료로 처리하지 않습니다.

## 자동 분류와 %

현재는 **로컬에서 실행되는 명시적 문구 규칙과 유사 사례 피드백**을 사용합니다. 외부 언어 모델의 학습이나 검증된 확률 모델은 아닙니다. 부정·가정과 단순 가능 여부 질문을 구분하고, 본인 취소를 부탁하는 완곡한 질문은 요청으로 읽습니다. 모호한 문맥은 검토 대상으로 남깁니다.

초기 근거 점수:

| 근거 | 직접 주문 연결 | 주문번호 미연결 |
|---|---:|---:|
| 셀러의 상품·옵션·증정품 재고/준비 불가 명시 | 90% | 72% |
| 셀러의 가격 오류 명시 | 85% | 70% |
| 셀러·물류 측 지연 명시 | 80% | 65% |
| 확인된 구매자가 먼저 한 취소·환불 요청 | 88% | 68% |

작성자 ID가 주문의 Buyer ID 또는 구매자 회원번호와 일치하는 요청만 구매자 요청으로 인정합니다. 두 채널의 대화를 시간순으로 합쳐 1011 발송 전의 선후 관계를 비교합니다.

- Seller의 재고 부족 등 안내 → Buyer 취소 요청 → 1011 발송: 셀러 사정에 따른 악용 의심입니다. 뒤늦은 구매자의 동의나 변심 표현으로 원인이 바뀌지 않습니다.
- Buyer 취소 요청 → 1011 발송: 앞선 셀러 사정 안내가 확인되지 않으면 고객 사정 근거로 분류합니다. 별도의 변심 표현은 필수가 아닙니다.
- 시각이 같거나 구매자가 먼저 보낸 메시지에서 이미 셀러 사정을 언급하면 선행 연락 확인이 필요한 검토 대상으로 남깁니다.
- 상세의 `확인된 대화 순서`에 최초 확인 연락, 셀러 사정 안내, 구매자 취소 요청, 판단 대상 메일 시각을 표시합니다. 최초 확인 연락은 수집 범위에서 확인된 첫 연락이며 전체 대화의 시작을 보증하지 않습니다.

### 배송 일정 판단 정책 (2026-09-16 사용자 기준)

- Buyer가 구매 후 사이트에 게시된 기존 발송예정일을 확인하고, 예상보다 늦어 취소를 먼저 요청한 경우는 고객 사정입니다. 배송이 늦다는 표현만으로 셀러 귀책으로 판단하지 않습니다.
- Seller가 먼저 재고 부족·입고 지연·발송 일정 변경을 안내하고, 그 때문에 Buyer가 취소를 요청한 경우는 셀러 사정입니다. 이후 1011 고객 사정 취소 요청을 보내면 악용 의심으로 분류합니다.
- 판단은 단순한 최초 연락자보다 취소 원인이 발생한 순서를 우선합니다. 문의 채널과 Claim History를 함께 비교하며, 구매자가 뒤늦게 취소에 동의해도 앞선 셀러 사정이 없어지지 않습니다.
- “배송이 늦어 취소”만 있고 게시된 예정일 불만인지 셀러가 일정을 변경한 것인지 확인할 수 없다면 검토 필요·신뢰도 산정 보류입니다. 사이트 예정일을 직접 조회한 것처럼 추정하지 않습니다.
- Claim History 메시지 조회가 끝나지 않은 주문은 판단 불가·추가 수집 대기로 표시합니다. 기존 Qpost·게시판 자료는 보존합니다.

상충 근거·주문 연결 모호성은 45~50%의 검토 대상으로 낮춥니다. 근거 부족·조회 실패에는 임의의 0%나 50%를 붙이지 않고 산정을 보류합니다. 고객이 환불을 요청했어도 셀러 사정에서 비롯되었으면 고객 사정으로 분류하지 않습니다.

%는 판단 근거의 명확성을 나타내는 **초기 규칙 점수**이며 실제 악용 확률, 정답률 또는 고의의 확률이 아닙니다.

### 회사·근무지 주소 배송 불가 (2026-09-16 사용자 피드백)

`勤務先など会社宛ての住所へのお届けが難しいため、現在、配送手続きを進めることができない状況となっております。`처럼 회사·근무지 수령 주소 때문에 배송을 진행할 수 없다는 안내는 **고객 배송지 사유**로 분류합니다. 이 문구로 주소 오타 여부까지 추정하지는 않습니다.

- 작성자가 확인된 셀러의 1011 발송 전 명시적 안내를 사용합니다. 질문·가정·단순 회사 주소 언급은 적용하지 않습니다.
- 재고 부족 등 별도의 셀러 사정 근거가 있으면 이 규칙으로 덮어쓰지 않습니다.
- 직접 주문 연결은 초기 근거 점수 80%, 미연결은 65%입니다. 미연결 대화가 여러 주문과 겹치면 검토 필요로 남깁니다. 점수는 검증된 정답 확률이 아닙니다.

## 피드백 적용

- 확정 라벨, 사유, 당시 근거 원문, 자동 판단·점수, 규칙 버전과 시각을 `data/monitoring/feedback.json`에 저장합니다.
- 사유는 참고 근거로 보관·표시하며, 자유 입력 내용을 임의의 새 규칙으로 실행하지 않습니다.
- 대화 선후 관계를 포함한 근거 유형이 같고 시간순으로 정규화한 대화 내용의 유사도가 85% 이상인 다른 주문의 최신 피드백만 참고합니다. Seller ID 자체를 판정 특성으로 사용하지 않습니다. 규칙 변경 전 피드백은 보존하고 재확인 대상으로 표시합니다.
- 같은 주문·반복 저장은 중복 가중하지 않습니다. 보류, 근거가 변경된 이전 판단, 근거 없는 사례는 학습 예시에서 제외합니다.
- 현재 분류에 동의하는 유사 사례는 건당 3점, 최대 10점까지 점수를 보강합니다. 최댓값은 95%입니다.
- 반대하거나 상충하는 사례는 검토 대상으로 되돌립니다. 명확한 근거 유형의 유사 주문 3개 이상에서 같은 판단이 확인되면 일부 검토 사례의 분류에 반영하되 최대 70%로 제한합니다. 주문 연결 모호성이나 근거 부재는 이 방식으로 해소하지 않습니다.
- 어떤 주문의 피드백을 참고했는지 `신뢰도 · 피드백 반영 근거`에서 확인합니다.

## 자동 실행

평일 오전 10시, 월요일에는 금·토·일을 수집하는 기존 설정을 사용합니다. 미확정 검토·판단 불가·보류 주문의 과거 날짜도 하루에 한 번 재조회합니다. 완료된 사용자 판단은 근거 변경 여부를 표시하되 자동으로 덮어쓰지 않습니다.

PC·프로그램이 실행 중이고 정상 사내 인증이 유지되어야 합니다. `모니터링 수집`으로 선택 기간을 다시 조회할 수도 있습니다. 관리자에 문의를 발송하거나 취소 상태를 변경하는 기능은 없습니다.

## 대화 문맥 재분류 (2026-09-16, 규칙 v5)

- 본상품뿐 아니라 약속된 증정품·옵션·구성품을 준비/확보할 수 없다는 셀러 안내도 재고·공급 사정으로 봅니다. `タンブラーをご用意することができません`, `在庫を確保することができませんでした`, 품절/완판 및 `无库存`를 포함합니다. 고객이 뒤에 취소에 동의해도 선행 셀러 원인은 유지합니다.
